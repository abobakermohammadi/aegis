Why Aegis exists

Agents fail in boring, expensive ways.

Capable agents still lose context, reuse stale proof, reintroduce fixed defects, or declare success early. Aegis makes those failure modes machine-checkable.

False completion

Free-text confidence is not proof. Required gates need fresh passing evidence.

Stale evidence

Relevant code changes invalidate prior proof. “Passed once” is not permanent truth.

Context loss

Checkpoints, decisions, blockers, and mission state survive across sessions.

Repeated regressions

Confirmed failures become regression memory and reusable protection.

The mission loop

Make progress inspectable.

Creative reasoning stays free. Completion stays anchored to persistent state and reproducible checks.

Evidence model

“Done” is a state, not a sentence.

Status text is information. Gates close only on fresh passing evidence — and reopen when the repo moves under that proof.

✓Executable checks bind to mission criteria.
✓Git drift marks prior evidence stale.
✓Open blockers block completion.
✓Secret-like strings are redacted before persistence.
Benchmark honesty: recorded results are self-runs that validate the harness. No external performance claim until the same agent runs both protocol arms with published raw evidence.
